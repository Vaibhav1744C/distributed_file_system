DFS Monitoring — I/O Buffer & Cache

Bounded producer-consumer buffer • LRU cache • Real-time metrics
Bounded Ring Buffer (16 slots)
REAL DFS

The bounded buffer is a 16-slot ring of MemoryChunk objects (BoundedBuffer<MemoryChunk>). During upload, the upload thread pushes chunks and a background TCP sender pops them. When all 16 slots are full, push() blocks via cv_not_full_.wait_for(). Live stats from /api/buffer.

LRU File Cache
LRU Chain (MRU to LRU):
REAL DFS

LruFileCache in include/cache/lru_cache.h. On HIT data is returned from memory without TCP round-trip. On MISS data is fetched from storage nodes then inserted at MRU position. On write/delete cache_.invalidate() is called. Live stats from /api/cache.

REAL DFS

During upload, coordinator splits file into 64KB MemoryChunk objects pushed into a 16-slot BoundedBuffer. On download, reassembled data is stored in LruFileCache (64-item doubly-linked-list + hashmap). The OS manages virtual memory pages via Windows VirtualAlloc transparently. The DFS does not implement paging or partition algorithms itself.

REAL DFS

Every file upload acquires an EXCLUSIVE_WRITE lock on the target path. Every download acquires a SHARED_READ lock. Implemented in LockManager (src/sync/lock_manager.cpp) using std::mutex and std::condition_variable. Rename operations acquire locks in alphabetical order (Havender ordering) eliminating circular wait.

Write-Ahead Log & Crash Recovery

ACID transactions • LSN journal • Automatic rollback on crash
WAL Journal
LSNTX IDOperationFile PathStateTimestamp
REAL DFS

Every file operation is wrapped in a WAL transaction. WalManager::beginTransaction() writes a PENDING entry to SQLite with an LSN before any data moves. After all chunks are stored, commitTransaction() marks it COMMITTED. If the coordinator crashes between those steps, runCrashRecovery() finds the PENDING entry on restart and rolls it back. All entries shown are live from /api/recovery.
